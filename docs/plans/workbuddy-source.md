# WorkBuddy 模型来源接入方案

- 状态：国内版源码已实施；现行行为见 [反向代理](../reverse-proxy.md)。以下原设计与调研记录保留为历史。
- 基线：Daylight `ab86ea7`；本机检测到 WorkBuddy 5.9.3，仅核对了应用版本，未读取登录数据或发送请求。
- 目标：在反向代理中增加 WorkBuddy 来源，使用用户授权的 WorkBuddy 账号获取其可用模型，并通过现有网关供下游客户端使用。国内版先行；国际版作为独立账号域，待单独验证。

## 现状与决策

Daylight 已有来源注册、账号状态、模型目录、模型设置、路由、Chat / Responses / Messages 转换及请求诊断。`proxy/qwenwork/` 是同类账号来源的组织参考；`proxy/providers.js` 注册来源；`public/proxy/source-page.js` 复用来源页面。下游仍使用现有本地网关及 API Key，不引入第二个代理服务。

[WorkBuddy Open API](https://open.workbuddy.cn/docs/openapi) 当前公开目录列出用户授权、本地助理和云端任务等接口，未列出直接模型目录及 Chat Completions 接口；其 OAuth 凭证不能据此假设具有模型调用权限。[WorkBuddy 自定义模型说明](https://intl.cloud.tencent.com/zh/document/product/1316/84496) 描述的是 WorkBuddy 调用外部模型，方向相反。[社区项目 workbuddy-proxy](https://github.com/banana770/workbuddy-proxy) 声称通过桌面登录态和非官方接口调用模型，并区分国内与国际版；这是可供调查的线索，并非官方承诺或本项目的验证证据。

提议优先寻找官方支持的模型调用与授权路径。若官方路径不覆盖账号模型，在确认接口访问及许可边界后，才考虑以明确标注的非官方适配接入；协议不明或凭证无法安全获取时，不展示可用来源。不会把开放平台的任务接口伪装成无状态模型推理，也不会把 Token Plan API Key 等同于 WorkBuddy 订阅账号。

## 调研门槛

实施前以目标 WorkBuddy 版本和用户许可为边界，完成以下调查；真实推理会消耗账号额度，需在执行前说明并取得相应授权。

1. 核实国内版的账号类型、模型列表、授权入口、令牌生命周期及可用额度；确认是否有官方开放的直接模型接口和允许的第三方调用方式。区分个人版、企业版、国际版及自定义模型。
2. 对非官方路径，核查社区实现的版本、许可证和来源，独立验证其描述；记录端点、身份绑定、请求及响应结构、错误和取消语义。任何复制或改编代码之前完成许可证与归属检查。
3. 仅在用户明确发起接入时检查登录材料。验证读取方式、系统权限、有效期、切号、退出和刷新是否会影响桌面端；禁止在日志或报告中保存令牌、完整请求或响应正文。若刷新会使桌面端凭据失效、不能可靠隔离，停止该方案并寻求独立授权路径。
4. 使用合成数据及模拟上游先建立契约；真实账号验证另行记录授权、版本、模型、费用影响和结果。目录读取成功不能视为推理或工具调用成功。

## 设计

### 来源与状态

提议增加 `proxy/workbuddy/`，按实际协议拆分认证、模型目录和 provider；只有上游确有专用编码时才增加协议模块。实现现有 `execute`、`listModels`、`snapshot` 和声明式能力契约，在 `proxy/providers.js` 注册。国内和国际版如身份、端点或协议不同，各自拥有独立来源 ID、凭据、设置和缓存；可复用已验证的公共代码，不按名称在网关堆条件。

页面复用现有来源页和账号控件，状态分别展示未接入、授权中、已保存、目录可用、授权失效及错误。凭据保存、连接、目录和实际推理分别报告；非官方路径明确标记兼容性限制。模型启用、容量和思考选项只展示上游声明或经验证的能力；额度无可靠接口时显示未知，不推测数值。

目录按账号身份及环境隔离，有界缓存并提供手动刷新。切号、退出、凭据更新使旧缓存失效；旧异步结果不得覆盖新账号。目录失败保留最近有效结果并标记不可用，不自动生成默认模型或将未验证模型标为可用。

### 认证与生命周期

优先使用可独立撤销的官方授权。若仅能复用桌面登录态，接入动作必须让用户明确选择并说明读取范围；只读桌面文件，绝不覆盖原文件。长期凭据进入 Daylight 现有受控存储，独立引用及账号状态按现有机制保存；不输出令牌到接口、页面、模型上下文、命令参数或日志。

登录、刷新采用 single-flight、截止时间和账号代次检查；取消、超时或切号后的结果不可提交。退出持久化，清理失败不能重新导入旧账号；重新接入须由用户主动触发。处理不可读凭据、钥匙串拒绝、过期和网络错误，分别给出可恢复状态。不得假定任何特定授权方式或将社区项目的凭据刷新策略直接作为安全保证。

### 推理与协议

上游原生协议由调查结果决定。Provider 校验模型和能力，交给现有共享协议转换及 gateway 路由；不复制一套 OpenAI / Anthropic 转换器。对不支持或无法无损转换的参数明确报错，避免静默丢弃工具、图片、思考参数或系统消息。流处理覆盖增量文本、工具调用、结束状态、错误和背压；取消向上游传播。仅在明确可重试的错误且尚未输出时按现有网关规则回退；已输出内容不重放，认证刷新仅在确认请求未执行或上游明确拒绝时重试。

模型同名沿用现有路由规则，按来源和账号隔离配置与观测。请求诊断只保存现有允许的状态和用量元数据；上游错误正文、提示词、工具参数及凭据不落日志。额度不足、限流、权限失效与网络故障分别归类，不把上游未知错误正文返回给调用方。

### 管理接口覆盖

| 功能 | 服务 / Web | Agent / 客户端 / Skill | 状态 |
| --- | --- | --- | --- |
| 查看来源、账号及模型 | 来源 `snapshot` / `listModels`；现有来源状态、模型接口 | `/api/v1/proxy/state`，`workbench.py proxy-state` | 现有通路；WorkBuddy 未实现 |
| 登录、取消、刷新、退出 | 来源 authentication 能力及现有来源授权接口 | `/api/v1/proxy/prepare`、`apply`、`loginState`；对应 proxy 命令 | 现有通路；授权形式待核实，WorkBuddy 未实现 |

| 目录 / 推理检查 | 现有来源 check，区分 catalog 与 inference | `/api/v1/proxy/{discover,test}` 及对应命令 | 现有通路；真实推理可能计费 |
| 客户端调用模型 | 现有 `/v1/models`、`/v1/chat/completions`、`/v1/responses`、`/v1/messages` | 现有网关客户端；协议能力需逐项验证 | WorkBuddy 未实现 |

## 验收与实施顺序

1. 完成上述调研门槛，记录可复现的脱敏证据与支持矩阵；确定国内版身份和协议后再实施。若没有可靠授权路径，停在调研结果，不发布不可用入口。
2. 用隔离 dataDir、凭据命名空间和模拟上游测试登录、取消、刷新并发、过期、切号、退出和损坏状态；验证不触碰真实客户端配置及凭据。
3. 覆盖模型目录、设置、身份隔离、错误、限流、非流式和 SSE、工具调用及多轮工具结果、取消、中断和输出后不重放；逐协议测试转换边界及不支持参数。增加 Agent API、capabilities 和 Skill 客户端的隔离验收。
4. 运行 `npm run check`、`npm test` 和对应代理回归；构建实际原生 App 并验证来源管理及代理生命周期。相关来源页覆盖窄宽窗口、键盘、加载、错误和账号切换。
5. 在获得真实操作授权后，用受控账号分开验证目录、文本、流式、工具、多轮及取消；记录版本、模型、扣费影响、实际结果，不记录敏感内容。真实网络或账号不可用时保留未验证状态。

实施完成后同步现行行为文档和覆盖矩阵，明确模拟、真实账号、原生 App 各层验证结果。安装、发布和同步外部 Skill 副本均不包含在本方案授权中。

## 2026-11-13 调研记录

本机 WorkBuddy 版本为 5.9.3；仅检查到桌面登录文件存在，没有读取文件内容。社区报告 5.6.0 起桌面令牌可能使用加密封装，因而不能假设旧版明文导入可用；避免依赖该文件及其刷新凭据。

[独立授权线索](https://github.com/cheaper-inference/OmniRoute/issues/17837) 报告国内版通过 `www.workbuddy.cn` 的插件授权流程登录，并报告该账号与 CodeBuddy 国内版不同。本轮对 `POST https://www.workbuddy.cn/v2/plugin/auth/state?platform=CLI` 发起不带账号的请求，HTTP 200、业务 code 0，返回 state，登录链接的 origin 为 `https://www.workbuddy.cn`、路径为 `/login`；对该 state 的未授权轮询返回 HTTP 200、业务 code 11217，无 access token。该测试只证明授权入口和待授权状态可用，不证明登录成功、账号范围、令牌续期或模型权益。

[社区代理源码](https://github.com/banana770/workbuddy-proxy/tree/42cc5ff06799878df59fb53b03715b4a73529e95) 使用 `copilot.tencent.com` 上的 `/console/enterprises/personal/models` 和 `/v2/chat/completions`，并声称上游只接受流式 Chat；其国内版依赖桌面登录材料。上述行为均未以本机 WorkBuddy 账号验证；社区源码采用非官方协议，模型目录与推理必须分别验证。另一[社区实现](https://github.com/icebears111/workbuddy2api/tree/0ced9aba2a736d95160ff94af7055499a643da41) 的国内版授权指向 CodeBuddy 域，不足以证明它与 WorkBuddy 国内版账号等价。社区许可证和第三方声明须在复用代码前逐项核对；本轮未复制其代码。

下一门槛：以用户主动授权的独立会话验证账号身份、模型目录、令牌刷新和桌面账号互不干扰，再以用户同意的受控请求验证文本、流式及工具调用。若无法验证账号隔离与恢复，不应接入产品。此时仍无 WorkBuddy 来源实现。

### 隔离账号探针结果

用户授权独立网页会话后，国内授权轮询成功并返回独立访问令牌和刷新令牌；探针仅在内存中持有令牌。使用该令牌请求上述模型目录返回 HTTP 200、业务 code 0，`cli` 目录有 16 个可用模型。这是本次账号的观察，不代表所有账号均有相同模型或权益。

对 `hy4free` 各发起一次流式文本和工具请求，两个请求的 HTTP 状态均为 200，分别收到 67 和 47 个解析成功的流事件和结束标记；在本次探针限定的 `choices[].delta.content` 与 `tool_calls` 字段中均未观察到正文或工具调用。未记录推理内容、工具参数或凭据。探针没有记录结束原因、思考事件或用量，无法确定是否为输出预算不足或协议差异，也无法将 HTTP 200 判定为推理成功。探针进程结束后未保留令牌，因此继续调查需要新的独立授权会话。刷新令牌轮换、退出恢复、桌面客户端登录状态以及多轮工具结果尚未验证。

结论：独立登录和模型目录已实测；模型推理、工具调用与凭据生命周期尚未满足实施门槛。本轮未添加产品来源、改动用户 WorkBuddy 配置或进行安装发布。

### 实施验证更新

国内版来源已按既有 Provider 和独立授权会话接入，代码位于 `proxy/workbuddy/`。使用真实独立会话观察到目录、刷新后目录、流式文本、工具调用和原生 Chat 工具结果续接成功；验证使用单个模型 `hy4free`，不能推断所有模型或跨协议多轮均已验证。相关源码、当前文档及部署状态以交付记录为准。

### 0.9.5 发布前验证

使用隔离数据目录与开发版原生 App，在用户授权的独立账号上完成登录、系统钥匙串保存、进程重启后的禁止交互读回、模型目录和刷新；通过本地网关用 `hy4free` 完成 Responses 和 Messages 的多个工具调用及全部工具结果续接。随后退出隔离账号。测试没有读取或覆盖已安装 WorkBuddy 的凭据；此结果不代表所有模型、参数、正式签名身份或用户钥匙串环境均已验证。Node 22.23.5 下 `npm run check` 与 751 项 `npm test` 通过。Node 22 会在继承代理环境时输出实验特性警告；钥匙串模拟子进程测试显式关闭 Node 警告，以免污染模拟的 Swift helper 错误输出，保留原有错误分类断言。
