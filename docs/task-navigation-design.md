## 背景与目的

当前侧栏把今天、收件箱、全部任务、已完成放在同一层级。实际上，今天是日期安排，收件箱是项目归属筛选，已完成是任务状态，三种维度混在一起。用户几乎不用收件箱，因此它不再占用固定入口。

项目和任务在业务上不重复：项目保存名称、关联目录等上下文，任务通过 projectId 归属项目，日期计划通过任务 ID 引用任务。界面上的重复来自同一组任务存在独立项目页面、全部任务页面和今天页项目概览等多种入口，却没有清楚表达它们属于同一任务视图。

本次侧栏只保留一个「任务」工作入口，「今天」移入任务页内部切换。项目作为任务内的归属筛选和上下文，不增加独立的项目一级入口。任务管理仍可独立于 AI 使用，项目路径仍只是关联数据。

## 需求内容：导航与项目列表

### 侧栏结构

新建任务保持当前位置。侧栏仅显示任务、AI 对话、反向代理、CLI 配置、设置五个页面入口；任务使用清单图标，CLI 配置使用终端图标。全部任务、今天、项目筛选和待办/已完成切换均在任务页内完成。

全部任务按项目分组呈现，每个组标题显示完整项目名和当前结果数量，组内不重复项目标签。点击组标题进入项目上下文，查看路径、编辑项目或打开相关 AI 对话。未归类作为任务分组与筛选项保留。项目不占用侧栏空间，也不显示悬浮项目层。

### 今天页面

保留日期、当前正在做、此前未完成安排提示、今日任务顺序，以及「待办 / 已完成」切换。移除右侧的全量项目概览，改为单列内容，桌面内容区最大宽度建议 1040px，窄屏沿用现有边距规则。

今天只回答当天安排了什么；未安排任务通过「选择任务」加入，不复制任务、不修改项目归属。待办包括 todo 与 active；今日已完成指仍在当前日期计划内且状态为 done 的任务，不按 completedAt 重新定义成当天完成记录。日期跨天时刷新当天计划并提示日期变化。

选择今日任务弹窗允许按项目和关键词查找，初始显示未完成任务，加入后显示已加入。今天页新建任务默认勾选加入今天，项目归属允许选择或留空。

### 任务页面

统一使用一套任务列表和编辑行为，状态为「待办 / 已完成」。全部任务时每行显示所属项目；选择项目时不再重复显示相同项目标签，页头提供项目完整名称、目录、编辑项目、项目操作菜单和「相关对话」。删除放入项目操作菜单，保留现有影响提醒和撤销规则。

桌面端项目选择以侧栏为主，不再增加一套常驻的项目 tabs。通过轻量筛选菜单可选择「全部项目 / 未归类」；当前项目筛选显示为可清除的条件。窄屏侧栏隐藏时，项目选择器包含所有项目。

搜索默认作用于当前范围、项目与状态，输入框或搜索结果标题显示作用范围；用户可明确选择「搜索全部任务」，此操作将项目条件清空、范围切到 tasks，保留状态条件。状态 tabs 计数按范围、项目、关键词计算，随后才按状态选择列表。搜索不再绕过当前状态条件。

主动点击今天、任务或项目入口时默认展示待办、清空关键词；点击任务入口同时清空项目筛选。状态切换保留范围、项目与关键词。访问 AI、设置等页面再返回时，恢复原任务范围、筛选、关键词和滚动位置，不重新默认化。刷新及浏览器前进后退以 URL 为准。

新建任务：项目筛选下默认该项目，全部项目或未归类下默认未归类；普通任务页默认不加入今天。全局新建按钮使用最近的任务视图上下文，表单明确展示默认归属。编辑任务保留实际归属，不因当前视图自动迁移。

### 收件箱处理

删除侧栏入口和固定 tab；界面中原「收件箱」「收件箱 · 暂不归类」统一改成「未归类」。未归类任务仍允许创建、检索、安排、完成与恢复，projectId:null 含义保持不变。不自动创建「未归类」项目，也不强制给旧任务补项目。

## 需求内容：视图状态与路由

引入独立 TaskView：scope 为 today 或 tasks；filter 为 all、unassigned 或 project（项目类型额外携带 id）；status 为 open 或 done；另含 query 和 day。任务实体仍只有 todo、active、done，open 是展示查询条件。当前实现不必引入状态管理库。

task view、项目元数据和 AI 页面不再通过同一个字符串混合表达。选择顺序固定为范围 → 项目 → 搜索 → 状态；计数位于状态筛选之前。今天按 plans[day] 顺序，全量任务沿用现有实体顺序，不借改版修改排序合同。

建议集中到 public/task-view.js 和 public/routes.js 两个小模块：前者是纯筛选函数，后者负责解析、序列化和旧路由适配。网页与 Node 可共用前者；原生 App 通过现有 JavaScriptCore 路径执行同一筛选函数。避免在侧栏、正文、AI 跳转各写一套判断。

| 新 URL | 行为 |
| --- | --- |
| #today&status=open | 当天未完成安排。 |
| #tasks&status=open | 全部未完成任务。 |
| #tasks&project=ID&status=done | 指定项目的已完成任务。 |
| #tasks&unassigned=1&status=open | 未归类的未完成任务。 |
| #tasks&project=ID&status=done&task=TASK_ID | 指定任务所在视图与任务编辑弹窗。 |
| #ai&conversation=CONVERSATION_ID | 精确打开指定 Daylight 会话。 |
| #ai&scope=task&scopeId=TASK_ID | 打开带明确关联的待发送新对话，不在导航时创建存档或发送消息。 |

project 与 unassigned 互斥，不能拿某个特殊项目 ID 作为未归类哨兵值，以免和合法项目 ID 冲突。关键词使用 q 参数并编码。用户导航使用 pushState，连续输入关键词使用 replaceState；popstate/hashchange 均由同一解析器恢复状态。先解析基础视图，再处理 task 弹窗，避免因同时含 tasks 和 task 而漏掉任务。

旧 #today 保留；#all 映射为 tasks/open；#done 映射为 tasks/done；#inbox 映射为 tasks/unassigned/open；#project=ID 映射为 tasks/project/open。旧 #task=ID 仍有效，按任务当前归属和状态打开，已完成任务不再落入看不到它的待办视图。旧 #ai、#proxy、#cli、#settings、#new、#new-project 保留。

不存在的任务/项目展示已删除或不存在提示，清除失效筛选并回到任务列表；不存在的会话显示错误和会话列表，不能按名称自动寻找其他对象。若编辑表单正在打开，延迟刷新列表并保留用户输入，提交时沿用版本冲突检查。

## 需求内容：对外接口与 Skill

### 保留业务契约

state schema 仍为 1；项目、任务、plans 的字段、ID 和语义保持兼容。GET /api/v1/state 的完整结果和 POST /api/v1/actions 的 action、expectedVersion、requestId、day、去重、batch、undo 保留。task.create 不提供 projectId 时仍得到 null。

operations、API 文档中 inbox 的说明改为「未归类（旧称收件箱）」；不能由于取消导航入口而拒绝 projectId:null。完成、开始任务、移出日期、级联删除、恢复的领域语义沿用当前实现。

### 增量提供统一任务查询

新增 GET /api/v1/tasks，参数为 scope=all|today、status=all|open|done、projectId、unassigned=1、query 和 day。默认 scope=all、status=all、无项目筛选、day 使用服务器 localDate。scope=all 在服务内映射为 TaskView 的 tasks；status=all 仅供查询与旧客户端使用，UI 仍只展示两个状态 tabs。

projectId 与 unassigned 不能同时提供；未知枚举、非法日期返回 400；明确指定但不存在的项目返回 404；合法条件零条任务返回 200。日期无效不能悄悄退回今天。参数和匹配规则由统一选择器实现，返回完整匹配结果，沿用现有任务数量上限，本轮不增加分页协议。

返回结构为 {version, localDate, selection, counts:{open,done,total}, tasks}。selection 是规范化的实际查询条件；counts 在相同范围、归属和关键词条件下统计所有状态，tasks 再按 status 筛选。查询不会修改 state 或 version，不返回 AI 历史内容。

沿用本地 Agent Bearer 认证和 Origin 限制。capabilities 保留现有 apiVersion、operations、reads、writes 字段，增量提供 taskQuery 的地址、参数与计数口径，旧客户端可忽略新字段。server.mjs 和 native/Server.swift 必须同时实现，不能网页服务可用而安装 App 不支持。

Skill 的旧 state --view all|today|inbox|done 保留原语义，尤其 all 包含所有状态、today 含已完成且保留计划顺序；inbox 是兼容别名，不等于新增一级入口。新增 tasks 子命令调用统一查询，显式提供 --scope、--status、--project、--unassigned、--query、--date，不改旧 state 输出或 export 内容。旧服务未声明 taskQuery 时报告功能暂不可用，并提示可用的旧 state 命令，不伪造新接口已支持。

同步更新仓库 Skill 的 SKILL.md、references/api.md、workbench.py、README.md、docs/development.md、docs/native-app.md。仓库 Skill 与用户机器上已安装的独立 Skill 是不同交付物；安装更新需单独执行并核对版本，不能仅改仓库后宣称外部 AI 已适配。

### AI 接口的范围

下述会话接口继续走现有 /api/ai 和 X-Workbench-Token 验证，属于应用内部协同接口；不把它们直接并入公开管理 API，也不让管理 API 的 state 自动返回会话历史。对外新增的任务查询与内部 AI 关联接口分别记录契约。

## 需求内容：AI 会话协同

### 主关联与背景引用分开保存

每个会话新增可选 scope，形状为 {kind:"workspace"}、{kind:"project",id:"..."} 或 {kind:"task",id:"..."}，另含 scopeVersion。一个会话有一个主关联，同一对象可以有多个会话。任务会话的所属项目从最新 task.projectId 推导，不额外复制 projectId 到会话，避免迁移任务后关联分叉。

主关联帮助定位和组织上下文，不是工具权限边界。AI 仍可处理用户明确要求的其他对象，跨对象变更要在草稿里显示实际对象；不依据筛选自动授权读代码或更改模型运行目录。

旧会话缺失 scope 时按 workspace、scopeVersion:0 解释，保留所有 messages、sessionId、模型配置和过程记录，不批量重写、不按标题猜关联。AI 元数据仍存在 ai/conversations 内，项目与任务 state 不添加 conversationIds，也不因绑定会话增加工作台业务 version。

已有 @ 历史会话引用 references 原字段继续使用。新增 objectReferences:[{kind:"project"|"task",id}] 表示用户本轮明确引用的业务对象，最多 5 个，去重后由服务端读取真实对象生成快照；它不改变会话主关联。输入菜单明确区分项目、任务和历史对话，使用完整名称与项目归属辅助识别，/ 技能选择不变。

### 页面上的协同入口

项目页头提供「相关对话」与「新建项目对话」；任务编辑界面提供「相关对话」与「讨论这项任务」。相关对话可在轻量面板查看，选择后打开完整 AI 页面，避免为了关联引入第二套聊天实现。

有多个相关会话时由用户选择「继续某一会话」或「新建对话」；不自动挑最近会话并追加消息。新建只准备 scope 和输入草稿，首次发送时沿用现有创建会话流程，打开菜单不创建空会话。

AI 页头显示可点击的主关联，并可从任务返回原筛选位置。会话列表支持「全部 / 当前关联」筛选。全局 AI 页面保留通用会话，切换任务页面不会暗中改变当前会话关联或发送对象上下文。

会话与对象的相关性由主关联、本轮明确对象引用，以及成功应用的 action 中真实对象 ID 推导，分别标注「直接关联 / 曾引用 / 曾更新」，按会话 ID 去重。项目相关列表可汇总该项目当前任务的相关会话；任务相关列表不把所有项目对话都算成任务对话。来源对话链接也从已应用操作导出，不在两份业务文件中维护双向数组。

### 新增/扩展的内部接口

| 接口 | 增量契约 |
| --- | --- |
| POST /api/ai/conversations | 增加可选 scope；省略仍是通用会话。创建新关联前核实对象存在。 |
| GET /api/ai/conversations | 增加可选 scope=workspace|project|task、scopeId、related=1；原无参数调用仍返回全部会话。列表增量返回 scope、scopeVersion、关联状态和关联原因，不扩展历史正文到列表。 |
| POST /api/ai/conversations/:id/scope | 用户手动关联已有会话或解除关联；提交 scope 和 expectedScopeVersion。运行、等待问题或草稿、正在应用时拒绝并返回 409。 |
| POST /api/ai/conversations/:id/message | 增加可选 objectReferences 和 viewContext；保留 text、references、skills。viewContext 只描述用户明确携带的视图条件，不包含客户端伪造的任务正文。 |
| GET /api/ai/conversations/:id | 增量返回 scope、scopeVersion、当前关联对象状态；原字段不删改。 |

scope 更新前验证对象，比较 scopeVersion，通过后递增并原子保存会话；同一目标、同一预期版本的紧邻重试可返回首次完成的结果，其他过期修改返回 409。变更不改历史消息、不换 sessionId，界面明确提示已有历史上下文仍保留，跨项目讨论优先新建会话。解除关联将 scope 设为 workspace，而不是删除会话。

对象不存在时，新绑定、新引用返回明确 404，保留输入供用户移除引用后重试。已有会话绑定对象后来被删除时不删除会话、不猜新对象、不清空主关联；标记为关联对象已删除，仍允许讨论历史，但不能把旧对象快照当成当前可写对象。

### 上下文与运行时适配

每次发送都根据会话主关联、用户选中的对象引用和显式 viewContext，从管理 API 最新 state 读取上下文。记录 capturedAt、stateVersion、服务器 localDate、真实 ID 和可读快照到当轮消息；历史快照用来解释当时讨论内容，写入前仍要读取最新业务状态。

workspace 默认仅提供当前计划摘要与工作台计数；project 提供项目名称、目录元数据、计数和最多 20 条未完成任务摘要；task 提供当前任务完整字段、归属及今日安排状态。超过摘要上限时明确 total、truncated 和获取更多数据的方法，不静默省略、不自动引用全部会话正文。历史对话引用保留现有数量与内容上限。新增对象备注的快照总量限制为 60000 字符，超过时请用户减少引用，不能无提示截断。

在共享 ai/service.mjs 中构造上下文载荷，然后交给 Codex 和 Qoder；二者继续使用现有恢复会话流程和工作目录。新增 daylight_get_context 只读工具返回当前主关联、最新上下文、stateVersion 和关联是否有效；daylight_get_workspace 的旧无参数返回保持原样。标题、备注、目录和历史文本统一标识为数据，不可提升为工具指令。

进入今天后点击「安排今天」时，显式 viewContext 包含 today 与用户看到的日期；会话主关联仍为 workspace。不把今天转换成不存在的项目，也不把上次打开的页面偷偷附加给已有会话。跨天继续讨论时显示上下文日期，由用户新一轮明确安排日期。

### 草稿应用、回看与同步

项目、任务变更继续走 daylight_propose_changes → 用户审阅 → /api/v1/actions。关联元数据不能绕过这个流程，也不能因为会话绑定项目就自动把新任务填入该项目；模型应基于用户表达和明确的主关联提出归属，草稿必须可见。

草稿除标题/备注外，人类可读地显示目标项目、任务状态变化和日期安排变化；task.create/update 支持在审阅卡片选择项目或未归类。编辑未涉及 projectId 的更新不能无意加入归属变更。保留 expectedVersion、requestId、batch 原子性、超时原请求重试、冲突重新核对与全局最新写入撤销。

应用成功后记录工作台 version、实际已应用 action 和可解析的对象链接。链接覆盖项目创建/更新、任务创建/更新/状态、计划变更等真实对象；已删除对象显示已删除，不生成指向其他对象的链接。查看已完成任务时自动选择已完成状态，查看迁移任务时读取其最新项目，批量创建仍复用服务端规范化后的实际 ID。

AI 应用后立即刷新任务计数、任务列表、相关会话信息；外部 Skill 写入仍走现有约 3 秒的版本同步。保留筛选、输入、滚动位置和 AI 草稿；筛选内任务全部完成时展示当前范围的空态，不跳到别的页面。自动刷新不关闭正在编辑的任务表单，不丢失 AI 输入框中的文字、历史引用或技能引用。

离开 AI 页面不会取消生成或应用草稿。侧栏 AI 入口显示运行或等待确认提示，轻量状态同步复用会话列表/状态接口，不再挂载一份聊天页面。返回后读取实际状态并显示待处理卡片。保留当前全局单个 AI 生成请求的约束，本轮不增加并发生成。

## 删除、恢复与兼容迁移

项目删除继续级联删除全部任务、日期引用，保留本地文件。关联 AI 会话保留并动态标记关联失效；因此不需要任务存储与会话存储之间的删除事务。立即 undo 恢复同一项目/任务 ID 后，关联自动恢复有效。任务迁移后 task scope 的项目展示自动跟随当前归属，历史引用和操作记录保留当时的快照。

任务 export 仍导出业务 state，不因此次关联混入会话正文、模型会话 ID 或凭证。AI 存档的备份与导出是另一项能力，本轮不改原导出契约。重启读取旧会话时应用缺省字段，不改变已有运行中断恢复行为。

## 验收标准

1. 侧栏任务入口仅任务；今天、项目及状态在页内切换，全部任务按项目分组，无项目悬浮层。
2. 有项目、未归类、active、done、今日已完成等样本时，列表和计数符合统一口径；空项目、长项目名、重名、窄屏和键盘操作均可辨认与访问。
3. 今天的任务顺序、加入/移出、当前正在做、重新安排、完成/恢复以及项目级联删除/undo 语义保持正确。
4. 状态切换保留条件；主动导航默认待办；往返 AI 恢复原任务上下文；搜索作用范围明确，已完成任务可直接通过链接定位。
5. 所有旧 Hash、新 Hash、浏览器返回/前进、桌面启动入口、AI 查看任务链接有效；不存在的对象提示清楚，不错开其他对象。
6. 新任务查询在 Node 和原生服务返回等价结果，非法条件和认证错误正确；旧 state/actions、去重、冲突、export 及 CLI view 语义不变。
7. 旧会话可读取、恢复和继续；scope 绑定仅通过明确操作，运行/等待阶段不允许重绑；重启后关联保留。原任务数据无需批量迁移。
8. 主关联、对象引用、历史对话引用、/ 技能同时存在时，服务端快照与模型实际接收到的上下文符合用户选择；项目目录不触发隐式扫描或运行目录切换。
9. AI 变更经过真实草稿审阅；修改归属生效；版本冲突不覆盖；未知结果重试不重复创建。应用后任务和项目计数同步，草稿和输入不丢失。
10. 删除关联对象后历史会话仍存在并显示失效；同 ID undo 后关联恢复；迁移任务后当前关联项目正确、历史快照不被重写。
11. 离开 AI 时生成继续、等待确认可发现，返回可继续处理；全局单请求限制、停止生成、模型切换、原生权限卡片、代理草稿保持正常。

## 评审结论与权衡

根据用户最后确认的方向，只保留任务入口，今天移入页内。项目实体保留，项目页面收敛为任务视图中的项目上下文；重复的是页面表达和导航层级，解决它不需要删除项目。

把会话主关联放在 AI 存档中，使业务 API、任务版本和撤销规则继续稳定；代价是相关会话列表需要按真实 ID 推导关联。以服务端快照和明确跳转解决协同，复用现有草稿机制，避免多处维护同一任务或同一会话的状态。

建议按上述六步实施，但作为一个完整变更验收：界面精简、外部兼容和 AI 协同都完成后，才能称为本轮修改完成。
