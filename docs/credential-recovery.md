# 代理凭证恢复

OAuth 来源（Codex、AGY、Grok、Kimi、Copilot）的令牌仍只保存在系统钥匙串中。`proxy/credentials/<source>-oauth.json` 只存当前凭证项和待清理项的引用，不存令牌。Qoder、千问办公使用各自原有的账号文件，不迁移到此存储。

## 登录与退出

新登录在独立凭证项中保存并读回校验，成功后原子切换当前引用。保存新凭证无需读取旧凭证，因此旧凭证授权失效不会阻止重新登录。首次读取保留对历史 `<source>-oauth` 项的兼容；新引用一旦存在，不再自动回退到历史项。

写入前先登记待清理项；进程在发布前退出时，旧引用仍是当前账号。发布失败或用户在提交前取消时，不切换账号。提交后的取消不会撤销已经保存的登录。旧项清理失败不改变新账号的成功结果；清理每次最多处理四项，每项采用一秒操作期限，保留未清理引用供后续重试。

退出先持久保存 `current: null`，再尝试删除本来源旧项。系统拒绝删除时，界面明确提示待清理状态；重启后仍保持退出，不重新启用历史登录。该提示不表示钥匙串中的旧项已经删除。AGY 的原 CLI 凭证始终不修改或删除。

## 用户主动恢复

启动、轮询和自动刷新禁止系统交互。共享 OAuth 账号遇到认证失败或需要交互时，会按 1、2、4 秒间隔最多进行三次静默读取；成功后自动恢复凭证访问，失败则保留「修复凭证访问」与重新登录入口。静默恢复不主动检测上游连接。修复操作允许系统授权：读取并验证旧会话，写入新的受管理凭证项，再禁止系统交互进行读回；静默读回成功才原子切换当前引用。仅一次读取许可不能算修复成功。失败、取消、超时保留旧当前引用，用户也可以直接重新登录。系统要求授权时，密码或确认次数由 macOS 决定，不能保证只输入一次。

修复接口仅验证凭证访问，不顺带刷新令牌或检测模型目录；返回 `credentialRepaired:true, connectionChecked:false` 后可用「刷新登录」独立检查连接，避免上游网络问题拖过修复授权期限。修复失败不保留成功提示；后续发现钥匙串仍需恢复时隐藏旧修复成功提示。前端不将缺失 `credentialRepaired:true` 的响应解释为成功。

只有主动授权后的保存和明确点击的修复操作允许系统授权窗口。后台期限为 30 秒，单次交互保存期限为 180 秒；整个修复事务共用 180 秒总期限，取消或超时后不能发布新引用，界面和原生转发为登录相关请求留出 210 秒。取消会终止对应助手进程；系统授权取消后可再次操作。服务端不会把上游模型目录检测失败当成登录保存失败。

## 更新与网络

正式助手保留历史签名标识 `DaylightCredentials`、`DaylightAgyCredentials`；发布时比较旧版 designated requirement。编译及签名缓存用于减少重复构建，不替代签名兼容检查。开发版 Daylight 凭证使用独立服务名，默认数据目录为 `~/Library/Application Support/Daylight Development`、管理端口为 4328，且不导入历史正式数据，避免覆盖正式凭证引用。显式设置 `WORKBENCH_DATA_DIR` 和 `PORT` 仍可覆盖默认值。

原生 sidecar 的出站请求最多每五秒重新读取一次 macOS HTTP/HTTPS 代理配置，显式代理环境变量继续优先。变化后新请求使用新连接池，旧连接池等待已有请求结束；系统查询失败时保留上次配置。不会因网络变化自动重放推理。PAC/SOCKS 自动配置不在本次支持范围内。

## 验收
