# 整体代码质量核查 · 2026-11-03

## 结论与依据

本次覆盖整个生产仓库，不限于最近改动。静态依赖分析覆盖浏览器、Node 服务、独立子进程和原生 JavaScriptCore 入口；人工复核重点是鉴权、任务写入、AI 生命周期、代理账号、扩展事务、配置写入和构建发布。

当前模块分层基本合理：共享 core 承担纯规则，Node/Swift 承担运行时 I/O，代理通过 Provider 接口扩展来源，扩展管理使用预览、事务和回执。修复本次确认的问题后，现有自动化与隔离验收未发现阻断问题。

“无孤立模块”是依赖图层面的可验证结果，不等于证明所有条件分支、动态样式或真实第三方服务永远没有缺陷，不能据此宣称可维护性已经达到绝对的“极高”。

## 已修复的问题

| 问题 | 处理 |
| --- | --- |
| 下线页面仍留在源码和资源清单 | 删除 18 个不可达前端文件、两个已无调用的原生类、专属 UI 测试和旧资源入口；清理 75 处下线样式选择器，约 6.8 KB 源码 |
| 旧统计链接和无效模板分支 | 删除统计链接、旧路由生成器及任务行已无调用的选择/排序/操作分支；旧 Hash 解析仍回到任务列表 |
| AI 保存失败后内存可能保留未落盘修改 | 保存成功后再发布新对象；已有对象写入失败时从原文件原位恢复，保持引用一致；临时文件始终清理 |
| AI 异步生成收尾保存失败可能产生未处理拒绝 | 捕获后台收尾失败，释放运行状态并显示保存错误；回归验证后续请求仍可发起 |
| 懒加载服务初始化失败会缓存拒绝结果 | AI/扩展初始化失败后清空加载 Promise，配置修复后可重新初始化 |
| 服务关闭路径重复调用且可能漏收异常 | 关闭过程复用一个 Promise，各资源用 allSettled 清理，统一汇总失败；关闭事件接住拒绝 |
| 并发凭证修复的取消所有权不明确 | 同一账号修复共享一个任务；取消精确中止其控制器 |
| 退出后的清理失败可能让退出响应失败，拒绝项可能堵住清理队列 | 已持久提交退出状态后，清理元数据失败返回待清理警告；失败项轮转，避免四个旧项永远阻塞后续清理 |
| DNS 校验完成后仍保留 AbortSignal 监听器 | 在成功、失败和取消路径统一移除监听器，增加重复请求回归 |
| 签名钥匙串解锁失败可能在异常命令中暴露密码 | 捕获解锁结果并返回本地错误说明，不输出解锁命令参数 |
| 检查脚本把 Git 中已删除但未暂存的文件当作待检查文件 | 仅检查工作区存在的文件；导入缺失继续由依赖图和测试发现 |

## 持续约束

`scripts/runtime-graph.mjs` 是资源检查与打包裁剪的共同依赖图实现，避免两套入口规则漂移。`npm run check` 已接入 `scripts/check-runtime.mjs`：

- 当前浏览器依赖 89 个文件、后端依赖 164 个文件；生产目录没有孤立 JS 模块。
- public 中无孤立 JS/CSS 文件，Web 资源允许列表与实际依赖一致。
- 独立启动的 AI MCP、Pi 扩展、sidecar、原生 JS 入口显式登记，避免误删动态入口。

新增运行入口、公共资源或运行模块时，检查结果必须一致；不能靠给孤立文件随意添加一个假入口来绕过检查。

## 仍需持续关注

1. 历史专注/日历服务仍是兼容 API 的实际调用链，故不属于死代码。本轮删除其下线 UI，未擅自删改用户历史数据；彻底退役服务需要单独移除 Agent/AI 契约并设计迁移。
2. `public/app.js`、`public/ai.js` 与扩展页面仍是较集中的界面编排层；继续新增功能时应按独立生命周期拆组件，避免继续堆分支。本轮没有为追求文件数量进行整仓重写。
3. AI 与任务仍使用本地 JSON 文件。同步 AI 保存对当前规模可用，但大量长对话下的磁盘延迟、整库启动成本尚无本轮规模预算；单个历史对话 JSON 损坏仍会要求先修复原文件，而不是静默丢弃。
4. 真实 CLI 授权、旧钥匙串 ACL、Gatekeeper 和证书轮换需要对应 macOS/账号的实际验证。模拟测试与签名校验不能替代真实授权体验。
